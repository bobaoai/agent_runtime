# P1. 仓位决策是期望值分解决策

## 1. 核心公理

任何仓位动作——减仓、持有、建仓——都是对"胜率 × 回报比 × 所处阶段 × 威胁情景"
四元期望值的回答，而不是对一个总暴露数字的回答。"降风险"必须能说出防的是什么
具体威胁；"持有/加注"必须能说出吃的是什么阶段的期望值。各板块胜率与回报比不同，
处置必须分桶差异化；把组合当一个数字去压，每一刀都不知道自己在防什么。

## 2. 深度推演

### 2.1 减仓是手段，防威胁才是目的

"我想减少暴露"的字面执行是把 Δ 数字压下来——按 Δ 贡献排序，逐个平仓。这个执行
方式的问题在于它对每笔仓位一视同仁：正常工作的收租腿、深回撤后的残值彩票、刚确认
反转的主题仓，在 Δ 排序里只是大小不同的数。而它们各自是不同的生意，各自的风险
来源不同。正确的起点是威胁建模：这个事件窗（如巨头财报周）具体怕什么——capex
叙事受挫打哪个桶、单票 gap 打哪条腿、板块分化抽走哪类高 beta、利率二阶压什么
估值。把威胁映射到书上，动作从映射推导，每个动作挂它防的情景。挂不上情景的
减仓就是为清而清。

### 2.2 进攻面与防守面同桌：阶段决定持有的期望值

威胁情景是防守面；反转阶段是进攻面。板块反弹刚开始且获得确认（组内破前日高的
广度、量能、资金流向）时，持仓的期望回报率最高——这恰恰是"考虑继续持有"的时刻，
即使事件窗就在眼前。两面冲突时的裁决不是二选一，而是结构化：已持仓靠垫位与
吊灯线扛事件，不在事件前追加（追加吃不到阶段红利，只多吃事件风险），期限撞
事件窗的腿问时序而非方向。

### 2.3 各桶胜率不同，禁全局一刀切

同一天里：确认反转日的存储/光模块（高胜率高回报比阶段）、已 run 到目标区的能源
强势仓（回报比衰减，兑现窗口）、分化另一侧的中国仓（胜率待验证，仓位本来就小）、
两头受力的宏观金（地缘买盘 vs 实际利率压制）。对这四个桶，"减仓控制风险"的正解
分别是：不动、兑现、不动、拍板题——而不是按比例各砍一刀。胜率与回报比的分桶
判断先行，仓位动作只是判断的执行。

### 2.4 分册分账户：不同生意不同问法

CSP 收租册与方向 Delta 册必须分账：收租腿的愿接**在下单时点已经回答完毕**——
卖出 CSP 本身就是按行权价接货的声明，持仓期不重开愿意问题，事件窗不构成恐惧性
买回的理由（指派=按计划接货进 wheel）。收租腿在持仓期的唯一问题是收益率运筹
（roll 是否 credit 划算），以及标的论点是否破裂（那是撤愿接条目的上游事件，
不是腿级犹豫）。方向册按主题桶拆，每桶挂阶段与情景。账户独立结算就独立分析——
同一价差在大户是配菜、在小户是主菜。口径细节沉在执行面设计文档；本公理管的
是问法。

## 3. 应用判定

**触发场景**：任何"减仓/降暴露/控制风险/该不该建仓/怎么调仓"的请求或自发建议。

**执行检查**：
1. 动作清单里每一条能不能说出"防什么情景"或"吃什么阶段"？说不出的删掉。
2. 有没有把收租腿按 Δ 排序砍、或向用户重问"愿不愿意接"？有就退回：愿接下单
   时已定，腿级只报运筹选项（roll credit 划算与否），不挂拍板项。
3. 有没有对不同胜率的桶用同一比例？有就退回分桶判断。
4. 反转刚确认的桶被列入减仓了吗？列入了要单独说明为什么防守面压倒阶段红利。

**反面信号**（违反本公理的典型话术）："①+②落地后总 Δ 从 77% 降到 59%"——只有
数字轨迹、没有威胁映射的减仓方案；"这腿明晚财报前拍：愿不愿意接"——把下单时
已定的愿接当成持仓期待决事项（2026-07-21 实测被用户纠："我下单的时候我就是
愿意的"）。

**源头**：2026-07-21 巨头财报周实盘三连拍——"你不能为了清仓而清仓"／"从巨头财报
担心什么这个角度分析"／"每个板块胜率不一样，减仓不单是降仓位，还有胜率跟投资
回报比的考量"。
