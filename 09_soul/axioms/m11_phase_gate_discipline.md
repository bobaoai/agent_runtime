# M11. 阶段门纪律

## 1. 核心公理

AI 执行多阶段或多单元工作时，注意力是有限资源。当注意力跨阶段或跨单元扩散，验证质量系统性下降——越靠后、越不显眼的检查越容易被跳过。

因此：每个阶段必须有显式退出标准（completion gate），逐项处理并验证达标后再进入下一阶段。不定义退出标准就开始执行，等于把质量判断权交给执行者的即兴判断。

## 2. 深度推演

### 2.1 Context window 的注意力衰减

AI 的 context window 不是均匀的注意力面。越多信息堆积，对单条信息的注意力越弱。在批量处理 N 个单元时，第 N 个单元的验证质量显著低于第 1 个——不是因为模型不够聪明，而是因为前 N-1 个单元占据了注意力预算。

这不是可以通过"更努力"解决的问题，而是 bounded attention 的结构性约束。唯一的系统性应对是：**缩小每次处理的单元数到 1**，让每个单元都享受完整的注意力预算。

### 2.2 隐式退出标准的危险

当工作流没有显式定义"什么叫做完了"，执行者（无论是 AI 还是人）会用自己的内隐标准。这些标准通常偏松：

- 执行者有推进任务的动力（进度 = 成就感），倾向于把"差不多"当成"够了"
- 越深入工作，越容易把"已经花了时间"当作"已经做到位了"
- 没有外部锚点时，"够好了"的阈值持续下移

显式退出标准是外部锚点。它把"觉得做完了"替换为"可以证明做完了"。

更危险的情况：退出标准存在但太松。"至少有 1 个 body section"和"必须含 Introduction/Results/Discussion/Methods/References"的差距，就是"看起来有东西"和"确认东西齐全"的差距。退出标准必须有齿——足够具体到可以用 checklist 逐条打钩。

### 2.3 阶段门防止跨阶段污染

工作通常分阶段：获取 → 处理 → 验证 → 分析 → 应用。当一个阶段的工作没做完就跳到下一个，两种错误同时发生：

1. 上一阶段的遗漏变成下一阶段的隐性假设（"数据应该都在了吧"）
2. 下一阶段的工作占据注意力，上一阶段的遗漏更难被回头发现

阶段门要求"先证明上一步做完了，再动下一步"。这不是流程负担，是对有限注意力的理性分配。审计报告是阶段门的载体——它把"我看了一下没问题"替换为"这里是结构化的检查结果"。

### 2.4 统一终点原则

每条处理管线应收敛到一个统一格式的终点产出。当管线的中间产物以多种格式散落在不同位置时，下游消费者需要自行判断"该用哪个"——这个判断本身就是一个错误源。

统一终点意味着：管线有一个明确的"最终产出物"，下游只需要消费这一个。中间产物是管线的内部细节，不暴露给下游。这既减少了下游的认知负担，也减少了格式不一致导致的静默错误。

## 3. 三条执行纪律

**纪律一：完成标准前置。** 每个工作流在执行前必须有显式的退出标准。标准必须可验证（不是"看起来差不多"，而是"满足条件 C1-C6 全部"）。标准在 design doc 里定义，不在执行时临时发明。

**纪律二：逐项处理。** 多单元工作逐个处理，每个单元验证通过后再处理下一个。批量处理只在注意力成本显著低于逐项成本时使用——在 AI context window 中，这种情况几乎不存在。

**纪律三：先审后析。** 当前阶段的所有产出经审计通过后，才能进入下一阶段。审计必须产出结构化报告（不是"我看了一下没问题"）。报告是阶段门的可检查证据。

## 4. 应用判定

### 何时适用

- 任何多阶段工作流（获取→处理→分析→输出）
- 任何多单元处理（逐篇论文、逐个文件、逐条数据）
- 任何需要多次迭代的工作（corpus 建设、知识库扩展）
- 任何产出需要被下游消费的管线

### 何时不适用

- 单步原子操作（一次文件编辑、一次查询）
- 纯探索性工作（头脑风暴、概念验证、想法收集）——但探索完成后进入执行时，门纪律恢复
- 真正的批量确定性操作（rename all、find-replace），其中每个单元的变换逻辑完全相同且不需要判断

### 在各工作台的表现

| 工作台 | 单元 | 阶段门示例 |
|--------|------|-----------|
| data_org | 单篇论文 | C1-C6 完成标准（metadata → 原件 → 读取面 → 交叉验证） |
| deep_read | 单篇论文 | 结构化读书笔记产出后才标记精读完成 |
| research | 单个科学家/子领域 | 画像/地图的每个子单元独立完成验证 |
| writing | 单个章节/修改轮次 | 每轮有明确检查标准（结构/论证/引用/格式） |
| review | 单篇审稿 | 每篇审稿完成全部维度检查后再审下一篇 |

## 5. 与其他公理的关系

- **T07 隔离-处理-验证闭环**：T07 定义了宏观三阶段模式（隔离 → 沙盒处理 → 人工闸门），侧重生产安全；M11 定义了每个阶段内部的门纪律，侧重执行质量。T07 说"验证后才发布"，M11 说"验证必须有显式标准，且标准在执行前定义"。两者互补，不重叠。
- **A04 可靠性是管理问题**：A04 §2.3 说"定义清晰的成功标准并自动检查"；M11 把这个原则从结果验证层扩展到执行过程层——不仅最终产出要有验收标准，每个中间阶段也要有退出标准。
- **V02 可验证性是信任的地基**：完成标准就是可验证性在工作流中的具体载体。
- **X03 效率由瓶颈决定**：在 AI 执行中，瓶颈是注意力质量而非处理速度。逐项处理看起来慢，但每步质量高、返工少，总效率更高。
- **FP3 追根因，不打补丁**：跳过阶段门的根因通常是"觉得上一步差不多了"——完成标准是对这个根因的系统性修复。

## 6. 反面案例

**批量 ingestion 导致遗漏。** 29 篇论文同时处理，DOI 错误、文件命名不规范、XML body 为空等问题在靠后的论文中被系统性忽略。改为逐篇处理后，每个问题都被发现并修复。根因：批量处理把注意力分散到 29 个单元上，每个单元分到的注意力不足以发现细节问题。

**跳过 ingestion 直接分析。** 论文还没全部转成统一 XML 格式（11 篇 PDF 没有读取面），就开始做引用网络分析。结果：分析基于不完整数据，需要返工。根因：没有阶段门——ingestion 阶段的完成没有被检查就进入了 analysis 阶段。

**退出标准太松。** C4 最初只要求"至少 1 个 body section"。用户发现 Results 和 Discussion 章节没有被检查——"至少 1 个"让一篇只有 Introduction 的论文也能通过。修复后要求 research 类论文必须含 Introduction/Results/Discussion/Methods/References。根因：退出标准没有齿，执行者按最低标准通过。
